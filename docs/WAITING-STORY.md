# 행사장 대기 화면 · 각자의 자리에서

## 원본 분석

아래 표의 번호는 제공된 `분석 출력 N.png` 파일의 번호다. 좌표 원점은 원본 왼쪽 위이며, 가로·세로를 독립적으로 정규화한다. 카메라와 가림 판단의 기준은 완성된 원본 그림이다.

| 장면 | 원본 크기 | 등록할 기준점과 가림 | 사용할 움직임 |
|---|---:|---|---|
| 1 연구개발팀 | 536×448 | 스포이드 끝, 비커 입구와 액면. 그림에 붉은 액체가 이미 이어져 있고 전면 유리가 액체를 가린다. | 비커 안쪽 액면의 좁은 타원에서만 잔물결의 빛을 표현한다. |
| 2 경영관리팀 | 536×448 | 벽 달력 오른쪽 위 일정 칸과 책상 위 차트. 사람의 머리는 달력 아래쪽을 가린다. | 이미 그려진 일정 칸의 종이를 은은하게 밝힌다. |
| 3 생산팀 · 배합 | 536×448 | 두 재료의 입구와 도착점, 중앙 축과 소스 표면. 중앙 축·재료 흐름을 피한 오른쪽 앞 액면에 작은 반사 영역을 잡는다. | 기존 소용돌이 옆 소스 표면의 빛이 천천히 변한다. |
| 4 생산팀 · 포장 | 1448×1086 | 노즐 세 곳과 대응하는 파우치 입구, 컨베이어, 오른쪽 상자. 손과 제품이 서로 겹친다. | 완성된 캡스파우트와 오른쪽 포장대로 시선을 유도한다. |

원본에 포함된 손, 도구, 재료, 노즐과 소스 줄기, 지게차·파레트는 고정된 한 레이어다. 독립 운반이나 충진을 재현하려면 분리된 전경과 가려진 배경 복원본이 필요하다. 이 버전에서 분리·복원한 물체는 없다. 제품 표기 역시 그림의 일부로만 사용한다.

## 재생과 자산

전체 주제는 “각자의 자리에서 맡은 역할을 다하는 우리가 모여, 맛있는 세상을 만든다.”이다. `Event.tsx`는 사전 설문·대기 단계에서만 스토리를 표시한다. 기존 행사 주제와 관리자 환영 문구는 스토리 위에, 설문·추천 상태와 시작 안내는 그 아래에 있다. 직원은 재생 도중에도 다른 장으로 이동할 수 있다.

| 파일 | 역할 |
|---|---|
| `public/waiting-story/scene-1.webp` ~ `scene-6.webp` | 제공한 PNG를 파일 번호 순으로 변환한 배포 이미지 6장. 긴 변은 최대 1080px이며 원본 비율을 유지한다. |
| 같은 이름의 JPG 6장 | 기본 이미지 로드가 실패할 때 사용하는 축소본. 둘 다 실패하면 장면 설명과 수동 이동을 제공한다. |
| `masero.png`, `hyeseong.png` | 마세로누끼.png와 혜성식품누끼.png의 검정·흰색 배경을 투명 처리하고 원본 비율로 축소한 PNG. 마지막 장면에서 제품 브랜드 다음에 회사가 나온다. |
| `src/components/waiting/story.ts` | 장면 순서와 원문, 원본 픽셀 기준점, 국소 효과 범위, 초점과 시간. |
| `WaitingStory.tsx`, `waiting.css` | 실제 HTML 그림·제목·캡션·로고·이전/다음·재생 제어. 이미지와 투명 효과 캔버스는 같은 부모에 들어가며 한 번의 변환을 함께 받는다. |
| `useStoryPlayback.ts` | 활성 시간, 화면 가시성, OS 모션 정책, 카메라와 페이드, 마지막 로고 순서. |
| `StoryLight.tsx`, `src/graphics/waitingStory.ts` | 공용 `createGraphicsSession`에 연결한 투명 셰이더. 원본 좌표로 작은 영역의 빛만 그린다. |
| `src/components/book/pageMirror.ts` | 장을 넘길 때 원본 이미지와 현재 카메라·밝기를 종이에 보존한다. 장식용 빛 캔버스는 복사 대상에서 제외한다. |
| `FrameReadout.tsx`, `src/App.tsx` | 개발 전용 앵커 검사 화면과 크기 표시. |

재생 시간은 순서대로 3.7, 3.7, 4.2, 4.2, 4.2, 6초다. 각 장면 양끝에서 0.4초 동안 종이색으로 밝기를 전환한다. 마지막 6초 중 마세로는 1.32초부터 나타나며 혜성식품은 3.54초부터 나타나 마지막 2.04초 동안 완전히 보인다. 줄어든 움직임을 선택하면 수동으로 장면을 넘기고, 마지막 두 로고는 순서대로 나란히 읽는다.

GPU에는 장면 이미지를 중복 텍스처로 올리지 않는다. 브라우저가 현재 그림을 표시하며 다음 그림을 미리 받는다. 공용 서비스가 효과용 평면 한 개, 셰이더 한 개와 렌더러를 관리하고 DPR을 1.5로 제한한다. 숨겨진 탭·화면 밖에서는 장면의 활성 시간과 렌더링이 멈춘다. 대기 종료 시 타이머·관찰자·애니메이션·재질·도형·WebGL 컨텍스트를 해제한다. 그래픽 실패 시에도 같은 HTML 스토리의 재생과 탐색을 계속할 수 있다.

## 확인 절차

휴대폰에서 장면만 바로 확인하는 주소는 `/#/preview/waiting-story`다. 배포에 포함한 정적 일러스트를 재생하며 직원 정보와 행사 상태를 요청하지 않는다. 직원용 행사장 주소는 `/#/event`다.

1. 개발 서버에서 `/#/dev/waiting-story`를 연다. **첫 프레임**, **장면 진행률**, **앵커 표시**를 이용해 효과를 정지한 상태로 검사한다. 원본 크기, 화면과 장면의 크기, 선택 진행률의 확대율, 장비별 좌표를 확인할 수 있다. 점선은 원본 전체 경계, 채운 영역은 빛이 허용되는 범위다. 로고의 안전 영역은 음식 그림 아래의 별도 칸이다.
2. 개발 서버를 5184 포트, 빌드 미리보기를 4173 포트에서 실행한 후 Node 24로 `node scripts/capture-waiting-story.mjs`를 실행한다. 다른 로컬 포트는 `STORY_DEV_URL`, `STORY_PREVIEW_URL`로 지정할 수 있다.
3. `artifacts/screens/waiting-story`에 장면별 0·25·50·75·100% PNG 30장, 기준점 이미지, 실제 WebGL 픽셀 검사, 6장면 전체 녹화와 순환 기록을 저장한다. 녹화는 빌드된 직원 행사장 화면에 가상 직원 응답을 연결해 생성한다.
4. 320·375·390·430·768·1280px에서 이미지와 효과 캔버스의 네 모서리를 비교한다. 768×375 가로 전환을 포함한다. 1~3번은 25% 프레임에서 원본 그림만 가리고 GPU가 그린 픽셀을 읽어 원본에서 별도로 측정한 허용 범위와 대조한다. 효과가 없거나 범위를 벗어나면 캡처 검사가 실패한다.

브라우저 회귀 범위는 대기·사전 설문 양쪽 진입, 여섯 장면 수동·자동 이동, 단계 변경과 해제, 공책 넘김, 저감 모드, 4배 CPU 지연, 기본 이미지 실패, WebGL 생성 실패·컨텍스트 손실, 초대장·실시간 힌트·공개 트리다. 실물 휴대폰, 실제 행사장 네트워크 및 운영 직원 데이터로 수행한 시험은 포함하지 않았다.

## 2026-11-16 로컬 검증 결과

프로덕션 빌드와 정적 검사, 단위 테스트 43개, 관련 Playwright 테스트 37개가 통과했다. 390px 녹화에서 1→2→3→4→5→6→1에 걸린 관측 시간은 약 26.2초였다. 모든 36개 장면·너비 조합에서 원본 표시 영역과 효과 레이어의 변 차이는 0 CSS px였다. 1~3번 장면의 분리 캡처 18장 모두 실제 발광 픽셀이 검출됐고, 지정된 원본 좌표의 허용 범위 안에 있었다.

검증 폴더의 `six-scenes.webm`은 전체 재생, `story-frames.zip`은 30개 프레임 원본, `frames-overview.jpg`는 프레임 모음이다. `reduced.png`와 `graphics-fallback.png`는 각각 동작 줄이기와 그래픽 실패 시의 실제 브라우저 화면이다.
