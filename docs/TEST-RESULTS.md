### 동시 연결 해석

50개의 독립 익명 Auth 사용자와 50개의 Postgres Changes WebSocket을 사용했다. 5명 명단을 유지하기 위해 같은 합성 직원 자격으로 바인딩했으므로 50명의 서로 다른 직원 데이터에 대한 시험은 아니다. 최신 실행(10:21 KST)의 힌트 1개 전송 지연은 p50 102ms, p95 102ms, 최대 102ms였으며, 50개 동시 snapshot 요청 묶음은 144ms였다. 재접속 후 공개 힌트 1개가 복구됐고 미래 힌트는 전송되지 않았다. 로컬 수치는 인터넷·모바일망의 성능을 보장하지 않는다.

### 보안 및 운영 경계

통합 테스트는 타인 설문·전체 원본·private RPC 접근 차단, 자기 추천 거절, 한 명당 한 표, 서버 기준 18시 경계, 비공개 힌트 차단, 리허설 격리, 오래된 revision 거절, 설문 마감, 동의 철회와 공개 승인 철회를 확인한다. 취향·추천 이유는 공개한 현재 단계뿐 아니라 다음 단계로 넘어간 뒤 철회해도 이전 감사 기록의 되돌리기로 복원되지 않는지 검사한다. 새 직원 세션의 bootstrap과 직접 public state 조회에도 철회 내용이 없는지 확인한다.

별도 운영 시험은 CSV 등록 후 무작위 코드 발급, 코드 재발급 시 기존 세션/코드 무효화, 위장 SVG 업로드 거절, 대기 중 사진 접근 차단과 RECAP 공개 후 다운로드, 개인정보 파기를 실제로 실행했다. 파기 직후 직원·설문·추천·바인딩·익명 Auth 사용자·Storage 파일은 모두 0이었고 관리자 접근은 유지됐다. 그 후 로컬 가상 직원 5명을 복구했다.

실제 관리자 화면에서 내려받은 XLSX의 ZIP 시그니처를 확인했다. CSV/XLSX 생성 경로의 수식 방어는 단위 테스트로 확인했다. Microsoft Excel에서 여는 수동 검증은 수행하지 않았다.

### 화면과 성능

320·375·768·1280px에서 로그인, 설문, 추천, 대기, 회고, 게임 준비/힌트 1~3/일시정지/정답, 취향 질문/결과, 시상, 엔딩, 마감 설문, 관리자 로그인·9개 메뉴·내보내기 확인을 촬영했다. 전부 합성 데이터이다. 화면 캡처는 용량과 개인정보 노출 위험을 줄이기 위해 Git에서 제외했다.

최신 캡처 전체에 대해 독립적인 디자인 시스템/기능 검수와 시각/한글 정밀 검수가 모두 PASS했다. 최종 보고서는 `artifacts/visual-integrity-gate.md`, `artifacts/visual-cjk-gate.md`이며 이전 REVISE 보고서의 줄바꿈·대비·대화상자·캡처 누락 문제를 새 이미지에서 확인했다. 검수 이력과 소스 해시는 `artifacts/REVIEW-LEDGER.md`에 있다.

로그인 Lighthouse SEO 점수는 63이다. 비공개 행사 사이트의 `noindex`와 `robots.txt` 차단은 의도한 설정이다. 대형 공통 JS의 소스맵·미사용 JS 등 진단 항목은 남아 있다. React Doctor의 초기 진단은 61/100으로, 모든 진단이 해소됐다는 주장은 하지 않는다.

검수에서 발견한 실제 오류는 수정했다: 500자 설문과 집계 스키마 길이 불일치, 늦은 bootstrap의 이전 상태 복원, 확인 창의 revision 변경, 공개 취향·추천 이유 승인 철회 반영 누락, HashRouter와 충돌하는 건너뛰기 링크, 어두운 패널 보조문구 대비, 대화상자 위치 및 좁은 관리자 미리보기 줄바꿈. 관련 회귀 테스트와 새 화면 캡처로 확인했다.

## 재실행

README의 로컬 설정 후 `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm test:integration`, `pnpm test:e2e`, `pnpm test:load`, `pnpm build`를 실행한다. 상태를 변경하는 통합/E2E/부하/운영/화면 캡처 스크립트는 순차 실행한다. `scripts/operations-test.mjs`는 로컬 가상 데이터 전체를 파기하는 시험이므로 운영에서 실행할 수 없도록 localhost를 검사한다.

운영 기본 연결 점검 후에도 관리자 설명서의 당일 점검표를 실제 휴대폰 2대 이상으로 수행하고, 전용 리허설 환경에서 50개 연결 시험·재접속·서명 사진 접근·권한 검증을 다시 기록해야 한다. 현재 행사 운영 데이터에 로컬 파기 시험이나 합성 시드를 실행하면 안 된다.

## 2026-11-12 · 로그인·대나무숲·직원 관리 변경 검증

- 단위 30개, 실제 로컬 Supabase 통합 30개 통과. 생년월일 6자리(앞자리 0 포함), 중복 차단, 직원 생성·영구 삭제와 세션 해제, 익명 글 저장/다른 계정 조회, 작성자 필드 부재, 제출 한도, RLS 우회 차단을 확인했다.
- 전체 Chromium E2E 5개 통과. 최종 문구 조정 후 신규 직원·대나무숲 시나리오 2개를 다시 통과했다. 320/375/768/1280px에서 10개 화면 상태를 총 40장 캡처했고 가로 넘침은 0건이었다. 모든 데이터는 로컬 합성 정보다.
- 새 로그인으로 독립 Auth/Realtime 연결 50개를 열어 50/50 힌트를 수신했다. 최대 324ms, 스냅샷 병렬 조회 137ms, 미공개 힌트 누출 없음. 물리 휴대폰 50대나 행사장 Wi-Fi 검증을 뜻하지 않는다.
- 로컬 운영 시험 9개 통과. 생년월일 변경으로 기존 비밀번호/세션 무효화, 사진 권한, 전체 파기를 실제 실행했다. 파기 직후 직원·설문·추천·세션·익명 글·게시 횟수·익명 Auth·Storage는 모두 0이며, 별도 관리자 접근은 유지됐다. 이후 가상 직원 5명을 복구했다.
- 기존 동시 진행 테스트에서 확인한 PostgREST의 SQLSTATE 40001 재시도 반복은 애플리케이션 충돌 코드 PT409로 수정했다. 동일 회귀 테스트가 제한 시간 안에 통과하며 HTTP 409 의미는 유지한다.
- 운영에는 테스트 명단을 넣지 않았다. 요청된 2명만 트랜잭션으로 삭제하고 나머지 명단의 모든 속성이 유지됨을 검사했다. 운영 직원 29명의 새 비밀번호 해시 일치 여부는 값 노출 없이 검증했다.

## 2026-11-13 · 같은 브라우저에서 직원 전환 로그인 수정

동일 브라우저에서 직원 A 로그인 후 로그아웃 없이 로그인 주소를 다시 열어 B의 올바른 비밀번호를 입력하면, 기존 익명 Auth ID가 A에게 묶여 있어 B를 거절하는 현상을 가상 직원으로 재현했다. 같은 B 비밀번호는 새 브라우저에서 성공했고, 수정 전 신규 브라우저 회귀 테스트 3개는 모두 실패했다.

로그인 시 이미 직원과 연결된 세션만 로컬 로그아웃하고 새 익명 세션을 만든다. 아직 인증되지 않은 세션은 잘못된 비밀번호 재시도에 재사용하므로 불필요한 익명 계정 생성을 막는다. 연결 확인 실패는 오류로 표시하고 기존 세션을 임의로 버리지 않는다. 다른 탭에서 계정이 바뀌면 이전 직원 화면과 미저장 양식을 로그인 화면으로 전환한다. 서버의 한 Auth ID당 한 직원 제한과 RLS는 그대로 유지한다.

검증 결과: 단위·통합 61개, 전체 브라우저 시나리오 9개 통과. 마지막 연결 오류 문구 정리 후 신규 로그인 시나리오 4개를 다시 통과했다. 320/375/768/1280px의 로그인·전환 전후·오입력·다른 탭 정리·연결 오류 상태를 24장 캡처해 독립 화면/기능 검수를 통과했다. 테스트 데이터는 합성 직원만 사용했고 운영 명단·응답·비밀번호는 수정하지 않았다. 반복 실행 중 발견한 기존 확인창 테스트의 오래된 문제 선택은 고정 시험 번호의 기존 문제를 갱신하도록 수정해 독립 실행과 전체 실행에서 같은 문제를 검증한다.

- 관리자 검수 승인 후 행사 시작·행사일 18시 이후 전체 글의 익명 사본을 마음 트리에 공개한다. 모든 직원은 실시간으로 새 페이지에 들어가 자유롭게 쪽지를 확대하고, 바깥 클릭·Esc·닫기로 돌아간다. 12개씩 가지를 넘겨 모든 글을 읽는다. 공개 종료/일정 변경/사이트 중단은 사본을 지우고 조회를 차단한다.
- Three.js는 트리 경로에서만 지연 로딩한다. 브라우저 공용 서비스가 셰이더 비동기 준비, 캔버스 재사용, 중복 종료, 리사이즈, 화면 밖/숨긴 탭 정지, 동작 줄이기, 효과 멈춤, 컨텍스트 손실을 관리한다. 트리와 눈은 독립 효과이며 반복 지오메트리·재질을 공유한다. WebGL 없이도 동일한 DOM 쪽지와 SVG 트리로 읽는다.
- 단위 32개와 실제 로컬 Supabase 통합 36개, 총 68개 통과. 브라우저 11개 시나리오 통과 후 최신 렌더러로 트리 흐름을 재검증했다. 실제 WebGL2, 같은 캔버스 재사용, 공개 전/다른 직원 차단, 내 글 삭제 취소/확정, 재접속·페이지 넘김, 확대·바깥 클릭·Esc·초점 복귀, 정지/동작 줄이기, 컨텍스트 손실 대체 화면을 검증했다.
- 로컬 운영/파기 10개 검증 통과. 실제 공개용 사본을 만든 뒤 직원·글·소유자·사본·횟수·설문·추천·세션·익명 Auth·Storage가 모두 0임을 확인했다.
